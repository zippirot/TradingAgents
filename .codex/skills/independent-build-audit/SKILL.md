# Independent Build Audit

**Claude Code prerequisites and limits.** (1) The `tradeframe-openrouter-audit` MCP server must be registered in Claude Code (stdio, `~/.codex/bin/tradeframe-openrouter-audit`, OpenRouter key in macOS Keychain). If its tools are absent, report the audit as not run; never simulate it or substitute a Claude review of your own. (2) The executor runs the Claude Code CLI against OpenRouter's Anthropic-compatible endpoint; whether it works end to end with the non-Anthropic default `openai/gpt-6-astra` has not been verified, so if a run fails on model or tool-use grounds, report that failure and, only with the user's approval, retry with an approved Claude alternative via an explicit `--model`. (3) `prepare-run.mjs` records repo-relative template paths under `.codex/skills/independent-build-audit/templates/`; the audited repository must contain those committed templates at HEAD (the Libertas repo does). (4) `pnpm`/`node` >= 20.11 are needed only to run this skill's own tests (`node --test test/*.test.mjs`).

Use only on an explicit user request for a final or interim audit, or when the approved implementation plan contains the exact standalone `Independent audit: required` marker under the repository's opt-in rule. Require a clean, committed, non-empty, plan-governed Git range. It must not auto-run merely for commits, build completion, goals, tuning, diagnostics, or recovery work without that authorization.

For a final audit authorized by the user or repository opt-in, first check that the decisive acceptance for the claimed build stage is complete and the material implementation is stable. Required native/provider proof must establish the defining behavior and relevant changed-boundary failure/recovery, not merely a successful fixture. If it is unavailable, keep that acceptance incomplete and continue independent authorized work; use bounded technical/safety review rather than repeatedly starting full completion audits. Approved separate release/installation deferrals do not block local-build audits. An explicit request or governing plan requiring earlier review takes precedence; label that review interim and preserve the missing proof. This timing rule does not waive required audits, complete suites, independent safety reviews, or existing access/spend limits.

Before freezing the candidate, establish the executor's actual inputs and permitted access. The installed frozen-manifest runner supplies the diff and HEAD contents of explicit `requirements_paths`; it does not automatically deliver the skill templates, external handoff, linked files, or predecessor source. Use the existing committed plan/report to identify relevant unchanged callers, safeguards, schema, and verification evidence. Where a material comparison needs BASE content, retain a bounded verbatim excerpt there with its exact commit/path; label excerpts and observed results separately from builder interpretation. Preserve historical evidence and approved deferrals. Do not copy secrets, raw user data, or an entire repository into the packet.

Before using the builder's check list, establish the audit stage and exact candidate/published SHA. Derive relevant checks from approved requirements, CI workflow and package scripts, shared contracts, and unresolved relevant failures. Separate selected-suite, complete-suite and exact-published-SHA CI evidence. A local unpushed build can be accepted locally with publication explicitly deferred; it cannot establish remote staging CI. A failed full suite contradicts selected green tests; a cancelled or missing CI run is unverified. Resolve contradictions before declaring a verdict, distinguishing pre-existing failures, introduced regressions and absent proof. Preserve supported feature acceptance while narrowing unsupported integration or release claims. Do not demand a quota of findings.

Select source by the changed behavior, not just changed filenames. Include the complete relevant producer/validator, error mapping, client classification and recovery consumer for a changed external contract, or the fresh/saved publication branches for an export change. Include prior regressions for the same failure mechanism and identify which new case they actually exercise. A changed-file list or a few diff context lines do not establish coverage of an unchanged function. Use bounded attributed excerpts in the existing evidence report when full source would exceed the packet limit; record omitted context rather than claiming complete coverage.

1. Run `prepare-run.mjs` (`node ~/.claude/skills/independent-build-audit/src/prepare-run.mjs`) with the approved plan, governing documents, base/head, explicit slug, and an explicit `--artifact-root` outside the audited checkout. Include the selected independent-audit instructions, existing evidence report, applicable CI workflow/package scripts, bounded exact-SHA test/CI receipts, and necessary unchanged source/schema paths in `--governing` so their supplied contents are hashed; these context files do not expand the approved requirements. Only include receipts that exist at frozen HEAD; put later or external receipts in a clearly identified handoff limitation, never claim they were supplied as hashed context. It treats the frozen plan size as a minimum, automatically escalates from the frozen audit surface when required, records declared/effective size plus reasons, and selects the matching turn/cost caps for the audit model. A dirty, invalid, unclassified, or in-checkout artifact scope is blocked.
2. Write `handoff.md` from the recorded `handoff-preparation` template and observed evidence only.
3. Call `tradeframe-openrouter-audit.start_completed_build_audit` (Claude Code tool name `mcp__tradeframe-openrouter-audit__start_completed_build_audit`) with the frozen repository root, base/head, those explicit paths as `requirements_paths`, the external run directory, the manifest effective build size, and the manifest model, soft-turn target, hard-turn cap, budgets, and emergency-duration cap. Confirm the submitted paths resolve at HEAD to the intended instruction/source/evidence contents; listing a template in the run manifest alone does not deliver it. Record supplied and unavailable context in the handoff. Poll `get_completed_build_audit` using its returned run ID until it returns a final report. Do not spawn the auditor directly or substitute a Claude subagent for the executor; the audit must run through the frozen-manifest executor. The soft limits signal convergence; they do not stop the audit. The executor also stops after ten minutes without observed streamed/output progress. A hard turn, spend, inactivity, or emergency-duration cap ends the audit and returns the best truthful partial result without requesting approval.
4. Write its structured result, including configured and actual turns, cost, elapsed wall-clock time, soft-limit state, and stop reason, to `audit.md`. An unavailable real dependency or runtime check is incomplete, never passed. Treat executor-generated `reviewed_files` as scope inventory unless actual inspection is evidenced. A structurally valid or completed executor result does not establish complete requirement coverage or build acceptance.
5. Verify each finding against code, diff, tests, runtime evidence, and logs, including material neighboring source or predecessor context absent from the auditor's packet. Write `findings-review.md`, using confirmed, partially_confirmed, not_reproducible, incorrect, already_resolved, or requires_user_decision. Record agreement, materiality, and action. Establish the unmet approved requirement, reachable failure, existing safeguards, and smallest complete correction. Missing evidence calls for bounded verification first; a partially confirmed claim supports only its verified portion, not speculative implementation.
6. Write a closure plan only for material confirmed or partially_confirmed findings. Validate the run before recording final status.

The auditor may use bounded read-only local commands and non-destructive local services only when supported and permitted by the executor; a frozen-evidence-only runner cannot independently exercise runtime paths. No edits, migrations, database writes, credentials changes, broker calls, or production-affecting calls are permitted. Record all mocked, simulated, substituted, unavailable, or unverified dependencies. If the required packet cannot fit or a selected external prompt variant cannot be supplied by the current interface, report the limitation and obtain the missing evidence through the authorized findings review; do not silently claim delivery, widen access, raise caps, or start repeated audits.

For an interactive reviewer with separately authorized tools, the model-neutral handoff at `docs/superpowers/handoffs/2026-09-22-independent-integration-audit.md` asks it to inspect exact-SHA CI and run permitted checks. Do not transfer that access assumption to this frozen executor. Its test/CI receipts are builder-supplied evidence, not tests independently rerun by Claude.

GPT-6 Astra (`openai/gpt-6-astra`, via OpenRouter) is the default audit model. The allowed alternatives are Claude Fable (`~anthropic/claude-fable-latest`, the original default) and `anthropic/claude-opus-4.8`. An explicit model override and any explicit limit override must be recorded in the manifest; it does not change the plan-derived build-size classification. An override may only reduce a plan-derived cap; raising a cap requires an updated approved plan.

After a terminal report is available, history persistence is attempted for an
owner-private, non-secret telemetry summary outside the worktree and artifact
directory at `~/Library/Application Support/Tradeframe-Audit/history/`. It records the run
identity and completion time, artifact location, frozen commits, plan build
size, requested/served model, configured limits, actual turns/cost/elapsed
time, soft-limit state, terminal status/stop reason, and finding counts by
severity. It never records frozen diffs, governing text, prompts, handoff or
audit text, environment variables, or credentials. Records are retained
indefinitely. Asynchronous polls retry the write idempotently when storage
recovers; synchronous direct audits have no later retry after a failed
history-write attempt. On an explicit request to inspect prior audits, call the read-only
`get_audit_history` on the same server with optional `limit` (default
20, maximum 100), `build_size`, `status`, or inclusive UTC `since` filters.
It returns successfully persisted summaries only, newest-first, with aggregates
by build size for exactly that returned limited cohort; it does not start or
modify an audit.

To select an approved prompt variant, pass its path and explicit version label to `prepare-run.mjs`: `--handoff-variant`/`--handoff-variant-version`, `--audit-variant`/`--audit-variant-version`, or `--findings-review-variant`/`--findings-review-variant-version`. The manifest records it as `user_supplied`; do not replace a default implicitly.
